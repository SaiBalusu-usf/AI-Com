# Dataset card — Cricket ball-by-ball commentary corpus

## Current status: SYNTHETIC PIPELINE DATA (pending human decisions D1)

The build environment's egress policy blocks every candidate raw-data host
(verified 2026-07-11, recorded by the proxy and in PLAN.md): cricsheet.org,
kaggle.com, huggingface.co. **Nothing was scraped and no blocked source was
routed around** (§2 rule 6, §4 fallback protocol). To keep the pipeline,
tests, and golden path real and runnable, the current dataset and the
committed 200-row fixture are generated by a seeded T20 simulator
(`src/cricket_commentary/data/synthetic.py`) that emits exact
Cricsheet-format JSON, parsed by the same `ingest.py` as real data.

Every row is tagged `data_source=synthetic`, `reference_source=synthetic_v1`.
All teams and player names are fictional. **Numbers computed on this data
validate the pipeline; they are never reportable research results.**

## Schema (JSONL, one ball per line)

```
record:   match_id, innings, over(1-based), ball(legal-ball no.), is_legal,
          batting_team, bowling_team, batter, bowler, non_striker,
          runs_batter, runs_total, extras, extras_type, wicket, wicket_type,
          player_out, fielders, team_score*, team_wickets*, target,
          balls_remaining, balls_bowled, innings_balls_total,
          batter_runs_after*, batter_balls_faced*, completed_over_runs, squad
          (* = cumulative INCLUDING the current ball)
features: current_run_rate, required_run_rate (chases only), wickets_in_hand,
          balls_remaining, phase{powerplay,middle,death}, momentum (runs off
          previous 12 legal balls), event_salience v1, tension v1
linearized_input: flat or context format (see data/linearize.py docstring)
target_commentary: reference text (synthetic_v1 until D1)
split: train|val|test — assigned BY MATCH (enforced by tests/test_splits.py)
data_source, reference_source: provenance tags
```

## Cleaning pipeline (identical for real data)

1. HTML strip + entity unescape + whitespace collapse
2. drop < 4 or > 80 whitespace tokens
3. drop regex entity-mismatch rows (commentary naming a squad member who is
   not the batter/bowler/non-striker/dismissed/fielder while never naming
   the actual batter or bowler)
4. exact-duplicate drop (first occurrence kept)
All drops are counted and reported in `dataset.stats.json`.

## Known limitations

- Synthetic outcome distributions are plausible-ish T20 rates, not fitted to
  real data; no player skill heterogeneity, no weather/DLS, no super overs.
- Synthetic references have bounded vocabulary; diversity metrics on them
  are optimistic for template-like systems.
- The excitement/tension correlation in references is by construction
  (documented in synthetic.py) so the §5.2 scorer validation is meaningful
  but easier than on real commentary.
